# INT8 Systolic-Array NPU in a RISC-V System (CNN + LSTM)

Open-source flow: SystemVerilog RTL, Verilator, PicoRV32 (sim), riscv gcc, Yosys/nextpnr.
FPGA target: Terasic DE10-Nano (Cyclone V 5CSEBA6U23I7) with Nios V, Quartus Lite (see `de10/`).

## Architecture
```
RISC-V CPU (PicoRV32 in sim / Nios V on DE10)
   | Avalon-MM (32-bit, 64 KiB window, readLatency 1)
   v
npu_avmm: weight / activation / accumulator / int8 result buffers + sequencer
   |-- sa_top: NxN INT8 weight-stationary systolic array (skew/de-skew inside, latency 2N-1)
   '-- post-processing: K-chunk accumulate, bias, requant (int16 mult, shift), ReLU / sigmoid / tanh LUT
```
Register map: header comment of `rtl/npu_avmm.sv`. Driver: `fw/npu.h`, tiled matmul: `fw/nn.h`.

## Layout
| Path | Content |
|---|---|
| `rtl/` | delay, pe, sa_top (array), npu_avmm (Avalon wrapper), lut_tables.svh (generated) |
| `sim/` | Verilator C++ unit test of the array vs golden GEMM |
| `soc/` | PicoRV32 + RAM + Avalon bridge testbench |
| `fw/` | firmware: gemm_demo, selftest, cnn (LeNet-5), lstm; model_*.h generated by `scripts/quantize.py` |
| `scripts/` | gen_lut.py, quantize.py (PTQ + bit-exact integer golden), bin2hex.py |
| `model/` | float training script + weights (LeNet 98.83%, LSTM 97.58%) |
| `results/` | logs of all simulation runs |
| `third_party/picorv32` | PicoRV32 (ISC license) |

## Run (on the LXC / any Linux with verilator, riscv64-unknown-elf-gcc, python3)
```
make test N=8                 # array unit test, 26 tests
make soc N=8 FW=selftest      # requant / accumulate / LUT vs C reference
make soc N=8 FW=cnn           # LeNet-5, CPU vs NPU, golden check
make soc N=8 FW=lstm          # LSTM, CPU vs NPU batch 1 / 16
python3 scripts/quantize.py   # regenerate fw/model_*.h (needs data/mnist.npz, model/*.npz)
```

## Results (PicoRV32 sim, N=8, cycles per image)
| Workload | CPU only | NPU | Speedup |
|---|---|---|---|
| LeNet-5 | 13.25M | 1.92M | 6.9x |
| LSTM batch=1 | 3.56M | 1.07M | 3.3x |
| LSTM batch=16 | 3.56M | 217K | 16.4x |

INT8 accuracy (10k MNIST test): LeNet 98.85% (float 98.83%), LSTM 97.50% (float 97.58%).
All NPU and CPU outputs match the integer golden model bit-exactly.

Limits: host-side im2col/pooling dominates the CNN time (about 1.2M of 1.9M cycles); LSTM element-wise cell update runs on the CPU; numbers are simulation on PicoRV32, not on the board.
